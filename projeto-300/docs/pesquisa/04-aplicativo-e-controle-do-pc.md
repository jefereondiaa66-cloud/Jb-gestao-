# Shell desktop Windows (Electron/Tauri/.NET/Flutter + caminho Android) + controle do computador + documentos + entrada de visão (telas, PDFs, câmera)

> Pesquisa feita em 02/11/2026 por agentes com busca na web, conferida por um verificador adversarial independente. Itens marcados como 'não verificado' não puderam ser confirmados na fonte oficial (alguns sites estavam fora da rede do ambiente de pesquisa).

## Resumo

Recomendo manter Electron, mas com três correções de premissa. (1) O Electron 45 (45.2.1, publicado em 31/10/2026; anúncio de 21/10/2026) traz Node v24.22.0, Chromium 156 e V8 15.6, e não Node 22. O Node 24 está em manutenção desde 20/10/2026 e o Node 26 virou LTS em 28/10/2026. Ferramentas e testes devem usar Node 24 para bater com o runtime (o unpdf, por exemplo, exige Node 24 ou mais). (2) Quase todos os módulos nativos do stack agora são N-API e já trazem os binários Windows dentro do tarball do npm: better-sqlite3 13.0.3, better-sqlite3-multiple-ciphers 13.0.3, sherpa-onnx-node 2.0.1, robotjs 0.9.1, @nut-tree-fork/libnut, koffi. Assim, @electron/rebuild e prebuilds por ABI do Electron (ABI 150) deixam de ser necessários, e é possível empacotar para Windows a partir de Linux. Os pacotes opcionais de plataforma entram com `npm install --os=win32 --cpu=x64`, que testei no npm 10.9.9. (3) O instalador NSIS do electron-builder 26.18.0 ainda precisa de Wine no Linux para gerar o desinstalador. Conferi isso no código de app-builder-lib 26.18.0, em NsisTarget.js. Os alvos zip, dir e portable saem sem Wine, porque a edição de recursos do .exe agora usa resedit, em JS puro. O NSIS final, que é o que o electron-updater exige, deve ser gerado no GitHub Actions windows-latest (Windows Server 2025 com VS 2026). O Tauri 2 (cli 2.12.4) gera instalador de 3 a 10 MB e usa menos RAM, mas obriga a empacotar um sidecar Node (pkg). Isso anula boa parte da vantagem e complica os addons nativos, então só compensa se o núcleo for reescrito em Rust. Para Android, o melhor caminho é um cliente fino (Capacitor 8.6 ou PWA, reaproveitando a UI web) ligado ao núcleo que roda no PC. O Electron não roda em Android. Controle do PC, em camadas: APIs e URIs primeiro; depois UI Automation (worker powershell.exe 5.1 persistente, ou helper .NET com FlaUI 5.0.0); depois Playwright com msedge e perfil dedicado; o loop computer_toolset_20260801 do Claude fica como último recurso. A entrada de mouse e teclado vai por robotjs 0.9.1, que voltou a ser mantido em 2026 com prebuilds N-API. O fork nut-js está parado desde 03/2025, e o nut.js original passou a ser pago. As capturas de tela vão por desktopCapturer (o screenshot-desktop grava e executa um .bat em %TEMP%). Para documentos: docx 9.15.1, exceljs 4.4.0 ou SheetJS 0.20.3 (nunca o xlsx 0.18.5 do npm, que tem CVEs high), printToPDF ou pdfkit, @cantoo/pdf-lib (o pdf-lib original está parado desde 2022), unpdf 2.1.0, mammoth e officeparser. OCR com tesseract.js 7 e os dados `por` vindos do npm, ou Windows.Media.Ocr pelo powershell.exe 5.1 (o pwsh 7 não tem WinRT). Assinatura de código: o Azure Artifact Signing (US$9,99/mês) não aceita pessoa física no Brasil, só EUA e Canadá. Para um usuário só, as opções viáveis são: sem assinatura ou com certificado autoassinado confiado no próprio PC, mais uma verificação Ed25519 própria das atualizações; ou a Microsoft Store via MSIX, que é grátis e assinada pela Microsoft. Atenção: o Smart App Control do Windows 11 bloqueia apps sem assinatura. Não consegui acessar diretamente electronjs.org, electron.build, tauri.app, learn.microsoft.com, openai.com e cdn.sheetjs.com. Usei os espelhos em raw.githubusercontent.com, tarballs do npm e resumos de busca.

## Recomendação

Electron 45.2.x + TypeScript (Node 24.22 embutido; ferramentas e testes em Node 24), empacotado com electron-builder 26.18.x. Builds de teste (zip/dir) saem do contêiner Linux; o instalador NSIS final sai do GitHub Actions windows-latest. Auto-update com electron-updater 6.8.11 via GitHub Releases e verificador Ed25519 próprio, enquanto a v27 com manifests assinados não sai. Processos: main só para janela, bandeja e permissões; um utilityProcess 'core' com o agente, o SQLite e os clientes de IA; um utilityProcess 'tools' com o controle do PC, que comanda um worker powershell.exe 5.1 persistente dentro de um Job Object. Controle do PC em camadas: (1) APIs, URIs e atalhos (shell.openExternal com allowlist, Start-Process de apps permitidos, APIs Google/Microsoft); (2) UI Automation (System.Windows.Automation no PS 5.1; helper .NET/FlaUI se o antivírus implicar); (3) Playwright channel 'msedge' com perfil dedicado (ou modo extensão para sessões logadas); (4) loop computer_toolset_20260801 do Claude como último recurso, com entrada via robotjs 0.9.1 e capturas via desktopCapturer. Documentos: docx, exceljs (ou SheetJS 0.20.3 embutido), printToPDF/pdfkit/@cantoo/pdf-lib, unpdf, mammoth/officeparser, tesseract.js 7 com 'por' local, e Windows OCR como acelerador opcional. Android: cliente fino Capacitor 8.6 com a mesma UI, falando com o núcleo do PC por WSS pareado.

**Alternativas:**

- Tauri 2.12 apenas se tamanho e RAM virarem requisito e houver disposição para reescrever o núcleo em Rust (o sidecar Node anula o ganho)
- Helper .NET (FlaUI 5.0.0, net48 ou self-contained, compilado no windows-latest) ou electron-edge-js 45.0.0 num utilityProcess, se o PowerShell com Add-Type for bloqueado ou sinalizado pelo antivírus
- @jitsi/robotjs 0.6.24 ou @nut-tree-fork/nut-js 4.2.6 como fallback de entrada, se o robotjs 0.9.x regredir
- Microsoft Store via MSIX (grátis, assinado pela Microsoft, sem SmartScreen) se o Smart App Control estiver ativo ou se o aviso de editor desconhecido incomodar
- Docker electronuserland/builder:wine para gerar NSIS no Linux, se o Actions não puder ser usado
- Everything (es.exe) se o usuário instalar; senão, índice do Windows Search; senão, fdir em pastas permitidas

**Justificativa:** O requisito de núcleo em Node/TS sem Python, com MCP SDK, SDKs de IA, sqlite-vec, sherpa-onnx-node e playwright-core, só é atendido de forma nativa pelo Electron. No Tauri o Node vira um sidecar empacotado com pkg, com addons frágeis, e o ganho de 80 a 90 MB some. O medo histórico de módulos nativos sumiu: better-sqlite3 13, multiple-ciphers 13, sherpa-onnx-node 2, robotjs 0.9 e koffi são N-API com binários Windows no próprio tarball, o que permite empacotar a partir de Linux e só gerar o NSIS no Windows. O controle em camadas segue o que UFO² e UI-TARS mostram (API e UIA antes de pixels): o loop de screenshots do Claude custa ~US$0,01 a 0,03 por passo e leva de 2 a 6 s, enquanto UIA e Playwright são grátis e respondem em milissegundos. A segurança tem que morar na nossa camada (ferramentas tipadas, níveis de risco, confirmação gerada pelo processo main, Job Objects, log de auditoria), porque no Windows nem o Claude Code tem sandbox nativa e o Constrained Language Mode não é fronteira de segurança sem WDAC. O Android como cliente fino evita reescrever o núcleo e respeita as restrições de foreground service de microfone do Android 14+.

### Prós e contras

**Electron 45.2.1 + electron-builder 26.18.0 + electron-updater 6.8.11**

- ✅ Node 24.22 embutido no processo main e nos utilityProcess: todo o ecossistema npm (MCP SDK, SDKs de IA, better-sqlite3, sherpa-onnx-node, playwright-core) roda sem Python
- ✅ Segurança madura: contextIsolation, sandbox de renderer (sandbox do Chromium no Windows), CSP, fuses (RunAsNode, NodeOptions, NodeCliInspect, EmbeddedAsarIntegrityValidation, OnlyLoadAppFromAsar, GrantFileProtocolExtraPrivileges, CookieEncryption)
- ✅ Módulos nativos N-API com prebuilds no tarball, sem rebuild por ABI (Electron 45 = ABI 150, segundo o node-abi)
- ✅ Auto-update NSIS diferencial (blockmap) pelo provedor GitHub Releases
- ✅ Electron 45: leitura direta de arquivos dentro do ASAR (até 100x mais rápida) e helper WER para crashes no Windows
- ⚠️ Instalador de ~85 a 100 MB só de base, e RAM ociosa de ~120 a 200 MB (fontes secundárias com números divergentes)
- ⚠️ Não roda em Android
- ⚠️ Mudanças que quebram compatibilidade no Electron 45: screen capture passou a pedir a permissão 'display-capture' em vez de 'media'; preloads com sandbox perderam Buffer, setImmediate e os shims events/timers/url; fds de arquivos dentro do ASAR só funcionam pelo fs (addons nativos e DLLs precisam de asarUnpack); os métodos síncronos do safeStorage foram depreciados e saem no 46
- ⚠️ Fuse RunAsNode=false faz child_process.fork lançar erro: é preciso usar utilityProcess.fork
- ⚠️ Por padrão o Electron aprova TODAS as solicitações de permissão se não houver handler
- Fontes: https://raw.githubusercontent.com/electron/website/main/blog/electron-45-0.md, https://www.electronjs.org/blog/electron-45-0, https://raw.githubusercontent.com/electron/electron/main/docs/tutorial/fuses.md, https://raw.githubusercontent.com/electron/electron/main/docs/tutorial/security.md, https://raw.githubusercontent.com/electron/electron/main/docs/api/app.md, https://raw.githubusercontent.com/electron/electron/main/docs/tutorial/electron-timelines.md, https://raw.githubusercontent.com/electron/electron/main/docs/api/safe-storage.md, https://raw.githubusercontent.com/electron/node-abi/main/abi_registry.json

- ✅ Os pacotes opcionais de plataforma (sqlite-vec-windows-x64, sherpa-onnx-win-x64, @koromix/koffi-win32-x64) instalam no Linux com `npm install --os=win32 --cpu=x64` (testado)

## Custo estimado

Shell, controle local e bibliotecas de documentos/OCR: US$0, tudo MIT/Apache/BSD. Distribuição: US$0 sem assinatura, com autoassinado ou pela Store/MSIX. O Azure Artifact Signing (US$9,99/mês) não está disponível para pessoa física no Brasil. Certificado OV custaria de ~US$65 a 220/ano, mais HSM ou nuvem (opcional). CI: repositório público grátis; privado a ~US$0,010/min no Windows (cerca de US$0,15 por build NSIS de 15 min). IA (estimativas, com cache de prompt): análise de uma imagem ou screenshot (~1,6k tokens de imagem + 1k de texto + 300 de saída) custa ~US$0,008 no Sonnet 5.5, ~US$0,016 no Opus 5.5 e ~US$0,0004 no Haiku 5.5; 50 análises por dia dão ~US$12/mês (Sonnet), ~US$25/mês (Opus) ou ~US$0,6/mês (Haiku). Computer use: 5 tarefas por dia de ~15 passos dão ~US$22 a 68/mês no Sonnet, ~US$45 a 135/mês no Opus e ~US$1 a 3/mês no Haiku. Por isso a regra é UIA, Playwright ou API primeiro, e loop de pixels só como último recurso, de preferência com Haiku ou Sonnet. Uso pessoal típico (poucas tarefas de pixels por dia, visão moderada): ~US$5 a 20/mês neste domínio.

## Riscos

- Prompt injection por conteúdo da tela, da web, de PDFs ou de e-mails levando a ações destrutivas ou a vazamento: exige níveis de risco, confirmação fora do alcance do LLM, deny-lists e log de auditoria
- Atualização sem Authenticode no electron-updater 6.x não verifica nada: um token do GitHub comprometido vira execução remota de código no PC do usuário (mitigar com verificador Ed25519 próprio ou cert autoassinado confiado)
- O Smart App Control do Windows 11 (instalações limpas) bloqueia o app sem assinatura; há relato de que a KB5127648 (10/2026) travou o toggle
- Antivírus e Defender podem sinalizar PowerShell com Add-Type/SendInput, o .bat em %TEMP% do screenshot-desktop e o exe sem assinatura
- Mudanças do Electron 45 (display-capture, shims removidos do preload com sandbox, fds no ASAR, safeStorage síncrono removido no 46) e do electron-builder 27 (win.sign, publisherName obrigatório, manifests assinados obrigatórios)
- O NSIS no Linux exige Wine (desinstalador). Contar com um runner Windows no CI
- O fork nut-js está parado (03/2025) e o nut.js oficial é pago; o robotjs voltou em 2026 com dependência de um único mantenedor
- DPI e multi-monitor: coordenadas do modelo, da captura e da entrada podem divergir em escalas de 125% a 175%
- UI localizada em pt-BR: automação baseada em Name quebra; use AutomationId e ControlType
- O Chrome/Edge 136+ bloqueia automação do perfil padrão; sessões logadas exigem o modo extensão ou um login no perfil dedicado
- Windows.Media.Ocr depende do pacote de idioma pt-BR e oficialmente pede package identity; o pwsh 7 não tem WinRT
- SheetJS no npm está congelado e vulnerável (0.18.5); cdn.sheetjs.com pode estar inacessível no build; o exceljs está com manutenção lenta
- Node 22 planejado vs Node 24 real do Electron 45: testes em Node 22 podem divergir (unpdf exige Node 24+)
- Android 14+: foreground service de microfone não pode iniciar a partir do background, o que limita a wake word contínua no celular
- O custo e a latência do computer use crescem rápido em tarefas longas
- Windows Sandbox não existe no Home; sem MSIX não há AppContainer prático para Win32

**Alternativas que a pesquisa inicial não considerou:**

- electron-builder 26.18.1 e electron-updater 6.8.12 (26/10/2026, dist-tag 'v26', fora de 'latest'): corrigem a troca de nome do electron_wer.dll no Electron 45, o update diferencial em runners de 2 CPUs e o envio de credenciais em redirects para outra origem. É preciso fixar essas versões explicitamente no package.json.
- toolsets.wine "1.0.1" no app-builder-lib 26.18.0: baixa um Wine 11 portátil do GitHub Releases (electron-userland/electron-builder-binaries, acessível do contêiner). Talvez permita gerar o NSIS no Linux sem Docker; não testado.
- uiohook-napi 1.5.5 (MIT, N-API com prebuilds, 03/2026) para push-to-talk de verdade. O globalShortcut do Electron só avisa quando a tecla é pressionada, não quando é solta, e também serve de detector global para o atalho de parada de emergência.
- winax 3.6.10 (MIT, 10/2026) para COM/ActiveX direto do Node: automação do Office (Word, Excel, Outlook), ADODB do Windows Search e CUIAutomation sem PowerShell. Contra: install com 'node-gyp rebuild' e sem prebuilds, então tem de ser compilado no windows-latest.
- node-screenshots 0.2.8 (Apache-2.0, napi-rs/xcap) para capturar janela ou tela fora do processo main, por exemplo num utilityProcess 'tools', como alternativa ao desktopCapturer.
- Empacotamento MSIX para a Store: alvo appx/msix do electron-builder ou electron-windows-msix 2.0.4. A Store permite listagem oculta ou privada, o que serve para um usuário só e resolve SmartScreen e Smart App Control sem pagar certificado. Requisitos de build no Windows não verificados.
- Node SEA (Single Executable Applications, nativo do Node 24) ou `bun build --compile` como sidecar do Tauri em vez de pkg. Não muda a conclusão, mas o relatório só citou o pkg.
- node:sqlite embutido no Node 24 como plano B do better-sqlite3 (com loadExtension para sqlite-vec, mas sem cifra). Disponibilidade dentro do Electron 45 não verificada.
- Recursos agênticos nativos do Windows 11 (Agent Workspace e MCP on Windows / On-device Agent Registry, anunciados em 2025): poderiam dar isolamento nativo e conectores de sistema para o controle do PC. Status em 11/2026 não verificado; vale investigar antes de decidir que 'não há sandbox nativa'.
- React Native for Windows 0.85.0 (10/2026) com Android: uma base JS/TS para os dois alvos, mas sem Node no desktop. Faltou na comparação junto com o Flutter; também perde para o Electron no requisito de núcleo Node.
